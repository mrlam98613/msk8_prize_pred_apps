# Z3 下載與比對重點

## 核心原則

Z3 crawler 每次可以照常下載資料，但只有確認「真的有新一期開獎資料」時，才會複製 CSV 到 `A_msk_lottery_data_folder/`。

如果沒有新資料更新，只寫入 `log/lotto_download_log.txt`，不覆蓋 WebApp 正式使用中的資料。

## 用哪個檔案判斷是否有新資料

用 `M2_last_upgrade_lotto_data.csv` 判斷。

比對兩個位置：

```text
Z3_ZH_lotto_2026_crawler/Lotto_Data_Folder/M2_last_upgrade_lotto_data.csv
A_msk_lottery_data_folder/M2_last_upgrade_lotto_data.csv
```

比對欄位：

```text
ndate
```

判斷方式：

```text
下載後 M2 最新 ndate > WebApp 目前 M2 最新 ndate
```

只有這種情況才代表有新開獎資料，才可以複製 `M1-M4` 到 `A_msk_lottery_data_folder/`。

如果：

```text
下載後 M2 最新 ndate <= WebApp 目前 M2 最新 ndate
```

代表沒有新資料更新，流程停止複製，只寫 log。

## M4 的角色

`M4_lotto_prize_summary.csv` 不用來判斷「有沒有新一期開獎資料」。

M4 只用來驗證本次下載資料是否完整，尤其是：

```text
last_draw_date
next_draw_date
week
```

目前檢查重點：

```text
M4 last_draw_date 必須等於 M2 最新 ndate
M4 next_draw_date 必須是 YYYY-MM-DD
M4 week 必須是 1-7
```

如果 M4 不完整，流程應該報錯並停止，不應複製到 `A_msk_lottery_data_folder/`。

## 為什麼不直接用 M4 判斷新資料

真正代表「開獎資料是否更新」的是 M2 的 `ndate`。

M4 是從 M3 摘要出來的下期資訊，可能因網站格式、CSV 寫入、欄位錯位而出錯。用 M4 判斷新資料會比較脆弱。

所以設計分工是：

```text
M2：判斷是否有新一期開獎資料
M4：確認最新一期與下期開獎日期是否完整
```

## 沒有新資料時的正常結果

網站部署後如果每 30 分鐘自動執行一次，很多時候都不會有新開獎資料，這是正常情況。

正常 log 例子：

```text
2026-05-20 01:02:51 沒有新開獎資料，略過複製。目前最新期：2026-05-19；下載最新期：2026-05-19；下期開獎日期：2026-05-21，星期：4。
```

這代表：

```text
下載流程成功
資料檢查成功
但沒有新一期開獎資料
所以沒有複製到 A_msk_lottery_data_folder/
```

## 有新資料時的正常結果

如果下載後 M2 最新 `ndate` 比 WebApp 目前資料新，流程會：

```text
1. 驗證 M2 最新 ndate
2. 驗證 M4 last_draw_date / next_draw_date / week
3. 複製 M1-M4 到 A_msk_lottery_data_folder/
4. 寫入 log
```

正常 log 例子：

```text
2026-05-21 22:15:00 發現新開獎資料並已複製完成。最新期：2026-05-21；下期開獎日期：2026-05-23，星期：6。


Z3 crawler:
  下載 M1
  合併 M2
  下載 M3
  用 M2 比對是否有新 ndate
  用 M3 驗證下期日期是否存在
  有新資料才複製 M1-M3

A1_seedBet_main.py:
  讀 M2 做回測/核對/策略
  讀 M3 取下期開獎日期
  寫入自己的 bet_data
```
